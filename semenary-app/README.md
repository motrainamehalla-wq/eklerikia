# موقع كلية البابا كيرلس والبابا شنودة الإكليريكية — المحلة الكبرى

موقع متكامل (Backend + Frontend) لإدارة الأعضاء، جدول المحاضرات، تسجيل الحضور
عبر كود QR، والتقارير. البيانات مخزّنة فعلياً على السيرفر (ملف `data/db.json`)
وليست فى متصفح كل جهاز، لذلك يراها الأدمن والأعضاء من أى جهاز.

## المحتويات
```
seminary-app/
  server.js        السيرفر (Express) وكل الـ API
  db.js             طبقة تخزين بسيطة (ملف JSON)
  package.json
  public/
    index.html      الواجهة (تتحدث مع السيرفر عبر fetch)
    logo.png         شعار الكلية
  data/db.json       يُنشأ تلقائياً أول تشغيل (لا تحذفه — فيه كل البيانات)
```

## التشغيل محلياً على جهازك (لتجربته قبل النشر)
يحتاج تثبيت [Node.js](https://nodejs.org) (نسخة 18 فأكثر) أولاً.

```bash
cd seminary-app
npm install
npm start
```
بعدها افتح المتصفح على: `http://localhost:3000`

- دخول الأدمن: الرقم القومى `admin` — كلمة المرور الافتراضية `2712` (غيّرها فوراً من "الإعدادات").

## النشر للاستخدام العام (خطوات مبسّطة)

أسهل طريقة مجانية وسريعة هى **Render.com**:

1. أنشئ حساب مجانى على render.com.
2. ارفع مجلد المشروع إلى حساب GitHub خاص بك (أنشئ مستودع جديد وارفع كل الملفات).
3. من لوحة Render اختر **New → Web Service** واربطه بالمستودع.
4. الإعدادات:
   - Build Command: `npm install`
   - Start Command: `npm start`
5. اضغط Deploy، وانتظر دقيقتين — سيعطيك Render رابطاً دائماً مثل:
   `https://your-college.onrender.com`

بدائل أخرى تعمل بنفس الطريقة تقريباً: **Railway.app**، أو أى استضافة تدعم Node.js
(مثل بعض خطط الاستضافة على DigitalOcean App Platform أو استضافات عربية تدعم Node).

> ملاحظة: فى الخطة المجانية على Render، السيرفر "ينام" بعد فترة عدم استخدام
> ويستغرق ثوانٍ ليستيقظ عند أول زيارة — هذا طبيعى وغير ضار بالبيانات.

## ربط دومين خاص بالكلية
بعد النشر، من إعدادات Render (أو أى استضافة) يمكنك إضافة **Custom Domain**
مثل `eklkolya-mahalla.com` وتوجيه الـ DNS الخاص بالدومين إليها حسب التعليمات
التى تظهر فى لوحة التحكم.

## نسخ احتياطى للبيانات
البيانات كلها فى ملف واحد: `data/db.json`. يُفضّل عمل نسخة احتياطية منه
بشكل دورى (تحميله من لوحة الاستضافة أو عبر SSH لو الاستضافة تسمح بذلك).

## الترقية لاحقاً لقاعدة بيانات حقيقية (اختيارى)
لو زاد عدد الأعضاء كثيراً مستقبلاً (آلاف المستخدمين)، يمكن استبدال `db.js`
بقاعدة بيانات مثل PostgreSQL دون تعديل أى شىء فى `server.js` أو الواجهة،
لأن كل التعامل مع البيانات يمر من خلال دوال `load()` و`save()` فقط.
